# swig: review findings and fixes

A sequential review of the swig component (2026-09-05) found 0 HIGH, 1
MEDIUM and 8 LOW defects in the two declaration-only packages that give
bindings generated by `swig4ada` their C types. All are fixed here except
the one under "Not changed". The names are a contract with the generator,
so nothing is renamed; the bindings in this tree are hand-maintained now
that the generator is unavailable, and the box2d and bullet glue are
adapted to the one changed type.

Severity: **HIGH** = wrong result, crash or memory unsafety on a path a
binding exercises; **MEDIUM** = wrong result on a common path or a hazard
one call away; **LOW** = latent, edge case or API trap.


## Findings

- **M1** `std_String` was one pointer, the pre-C++11 libstdc++ layout; the
  C++11 ABI, default since GCC 5, makes `sizeof (std::string)` 32 on this
  toolchain, so a binding passing one by value or building the
  `std_string_array` would have corrupted memory. Nothing used it. The type
  is now opaque with unknown discriminants, so no object of it can be
  declared, and only `std_string_pointer` remains; `std_string_array` is
  gone.
- **L1** `bool` was `plain_char`, an unsigned byte, so bindings passed
  `Boolean'Pos` and tested results with `/= 0`. It is a subtype of GNAT's
  `Interfaces.C.C_bool` now, a one-byte C-convention Boolean, and the
  box2d and bullet glue convert with `swig.bool (…)` and `Boolean (…)`.
- **L2** `long_Long` and `unsigned_long_Long` are subtypes of
  `Interfaces.C.long_long` and `unsigned_long_long` instead of
  re-declarations.
- **L3** `void`, `void_ptr`, `opaque_structure`, `incomplete_class`,
  `opaque_structure_ptr` and `incomplete_class_ptr` each say what C type
  they model; the last two are pointers to pointers.
- **L4** The package comment states that the numeric pointer instances'
  zero terminators serve only the length-free `Value` and
  `Virtual_Length`; the "tbd" note is gone, and `bool_Pointers` terminates
  on `False`.
- **L5** `void_Conversions`, which converted an address to an
  access-to-address, is removed; nothing used it.
- **L6** `c_math_thin.gpr` and the egl linkage test no longer depend on
  swig; the test declares its `void*` as `System.Address`. (The review
  said bullet's dependency was needless too; that was a case-sensitive
  search missing `Swig.opaque_structure`, and bullet keeps it.)
- **L7** The comment on `chars_ptr_array` now says what it means:
  `Interfaces.C.Strings` declares no aliased array of `chars_ptr`.
- **L8** `interfaces.C` is spelt one way, `Unsigned_8` and the standard C
  type names are cased as in `Interfaces.C`, and the stray apostrophes in
  the section comments are gone.


## Not changed

- `swig.Pointers` cannot be `Preelaborate`: its `void_ptr` and `chars_ptr`
  instances take `System.null_Address` and `null_ptr` as terminators,
  which are not static.
- `3-mid/physics/implement/box2d/source/thin-orig/` is an untracked copy
  of the box2d thin binding, outside the project's source directories.


## Verification

- swig builds warning-free with `-gnatwa`, and so do `build_all` and the
  egl linkage test.
- The box2d and bullet jointed demos (2D joints, hinged, chains) and the
  mixed shapes demo run 240 frames and exit cleanly, and their frames are
  pixel-identical to the renders made before the change.
